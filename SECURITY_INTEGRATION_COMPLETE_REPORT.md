# Состояние интеграции security-слоя

Документ фиксирует текущее состояние интеграции механизмов безопасности в проекте. Это не маркетинговый отчёт, а рабочая справка для разработчиков.

Актуальность: 2026-05-09.

## 1. Интегрированные компоненты

| Компонент | Статус | Комментарий |
| --- | --- | --- |
| `BaseController` | используется | Общий security API для контроллеров. |
| `SecurityService` | используется | CSRF, rate limiting, sanitization, SQL whitelist, заголовки, логи. |
| `PageSecurityHelper` | используется | Помощник для standalone-страниц. |
| `security_init.php` | используется | Инициализация защиты страниц верхнего уровня. |
| `AuthController` | используется | Сессии, вход, выход, проверка сессии. |

## 2. Контроллеры

Текущие контроллеры находятся в `src/Controller` и наследуют `BaseController`.

| Контроллер | Security-требования |
| --- | --- |
| `AuthController` | Rate limiting входа, безопасная работа с сессией. |
| `DeviceController` | Авторизация, валидация параметров поиска и экспорта. |
| `DeviceDataController` | Авторизация, CSRF для изменений, prepared statements. |
| `TestingController` | Авторизация, валидация данных испытаний. |
| `RepairController` | Авторизация, валидация ремонта, история изменений. |
| `InspectionController` | Авторизация, валидация данных контроля. |
| `ProductionController` | Авторизация, валидация lifecycle-записей. |
| `TerminationController` | Авторизация, валидация прекращения эксплуатации. |
| `AdditionalDataController` | Авторизация, очистка текстовых данных. |
| `FileController` | Авторизация, контроль размера и метаданных файлов. |
| `MessageController` | Авторизация, rate limiting отправки сообщений. |
| `ToleranceController` | Авторизация, административные ограничения при сохранении. |
| `AiAgentController` | Авторизация, rate limiting, read-only SQL для LLM. |

## 3. Страницы верхнего уровня

Страницы должны подключать `security_init.php`:

- `AccountingOfDevices2.php`;
- `profile.php`;
- `admin_panel.php`;
- `backup.php`;
- другие standalone-страницы, если они добавляются вне `front.php`.

Для новых страниц используйте `SECURITY_USAGE_GUIDE.md`.

## 4. AI-агент

Security-интеграция AI-агента включает:

- ограничение частоты запросов;
- системный prompt с правилами read-only SQL;
- запрет на выборку `users.password` и `uploaded_files.file_data`;
- выполнение SQL через `DatabaseSchemaService`;
- сохранение диагностических логов;
- контекстные фреймы в пользовательской сессии.

Особое правило: контекстные ссылки без найденного объекта возвращают `context_missing`, а не передаются в LLM.

## 5. Логи и аудит

Файлы:

- `logs/security.log` - события безопасности;
- `logs/error.log` - ошибки приложения;
- `logs/ai/*.log` - диагностика AI-агента.

Для production-эксплуатации рекомендуется настроить ротацию логов и исключить попадание секретов в debug-вывод.

## 6. Известные технические ограничения

- В проекте нет Composer и DI-контейнера; зависимости создаются вручную.
- CSP пока использует `unsafe-inline`, что упрощает поддержку текущего legacy-frontend, но требует внимания при усилении политики.
- `config.php` содержит конфигурационные значения; для production их желательно перенести в защищённое окружение.
- Отдельные страницы верхнего уровня требуют дисциплины подключения `security_init.php`, так как они не проходят через `front.php`.

## 7. Поддержка интеграции

При добавлении новой функции разработчик должен обновить:

- контроллер или сервис;
- security-валидацию;
- route/JS-вызов;
- документацию, если появился новый публичный контракт;
- AI-инструкции, если изменилась схема БД или правила SQL.

Контрольный список находится в `SECURITY_USAGE_GUIDE.md`.
