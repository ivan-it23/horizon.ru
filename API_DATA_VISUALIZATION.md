# API для приложения «Визуализация данных»

Приложение визуализации загружает файлы приборов в карточки напрямую, без
ручного выбора файла в браузере. Обмен идёт через тот же `front.php`, что и
остальные контроллеры.

## Что добавлено

| Файл | Назначение |
| --- | --- |
| `src/Controller/ApiController.php` | точки входа для приложения |
| `src/Controller/ApiTokenController.php` | создание и отзыв токенов из «Профиля» |
| `src/Service/ApiTokenService.php` | выпуск, проверка и лимиты токенов |
| `profile.php` | карточка «Доступ для приложения «Визуализация данных»» |
| `sql/2026-08-15-device-registry-api.sql` | структуры БД (создаются и автоматически) |

Изменено:

- `config.php` — `MAX_FILE_SIZE` поднят с 10 до 20 МБ;
- `src/Controller/FileController.php` — лимит загрузок 10 → 20 в час и
  заполнение контрольной суммы `sha256` при загрузке через сайт.

## Структуры БД

- таблица `api_tokens` — токены доступа. Хранится только SHA-256 токена,
  исходное значение показывается пользователю один раз при создании. Создаётся
  автоматически при первом обращении: таблица пустая и лёгкая;
- колонка `uploaded_files.sha256` — контрольная сумма файла для защиты от
  повторной загрузки того же содержимого. **Добавляется один раз вручную**
  скриптом `sql/2026-08-15-device-registry-api.sql`.

Колонка не создаётся кодом намеренно: при `ALTER TABLE` MySQL пересоздаёт таблицу
целиком, а в `uploaded_files` лежат файлы приборов, и на время операции нужно
вдвое больше места на диске. Внутри обычного запроса это недопустимо.

Пока скрипт не выполнен:

- загрузка через сайт работает как раньше, но без контрольной суммы;
- загрузка через приложение отвечает `schema_not_ready` с указанием, что нужно
  выполнить скрипт.

## Серийный номер прибора

Серийным номером считается поле **«Номер»** метрологии — номер для внутреннего
учёта, совпадающий с `device_identification.serial_number`. Поле «Серийный №»
предназначено для заказчика и в поиске приборов не участвует.

Номер закодирован в сигнатуре прибора: `(сигнатура & 0xFFFFF) % 1000`. Поэтому
приложение определяет прибор и по файлу метрологии, и по любому файлу данных.

## Авторизация

Токен передаётся заголовком `Authorization: Bearer <токен>`. Если конфигурация
Apache вырезает этот заголовок, принимается `X-Api-Token` или поле формы
`api_token`.

Все ответы — JSON. В отличие от сессионного `requireAuth()`, который делает
редирект на `index.php`, API при отсутствии или недействительности токена
отвечает `401` с телом `{"success":false,"code":"unauthorized",...}`.

Лимит: **20 загрузок файлов в час на токен**. Счётчик хранится в самой строке
токена — сессии у API нет, поэтому общий сессионный лимит здесь неприменим.

## Точки входа

Все — `POST` на `front.php?c=Api&a=<действие>`.

| Действие | Параметры | Ответ |
| --- | --- | --- |
| `whoami` | — | учётная запись токена |
| `dictionaries` | — | соответствие типов приборов и разделов карточки |
| `deviceResolve` | `serial_number`, `device_type`, `transmitter_count` | один прибор с номером корпуса |
| `deviceSearch` | `device_type`, `transmitter_count` | список подходящих приборов |
| `fileUpload` | `field_name`, `serial_number`, `case_number`, `device_type`, `file`, `file_name`, `sha256`, `force` | загруженный файл |
| `fileList` | `field_name` и тройка прибора | ранее загруженные файлы раздела |

`field_name` — те же четыре раздела, что и на вкладке «Файлы»: `thermoprofile`,
`metrology`, `calibration`, `kis`.

`device_type` принимается как код приложения (`Autonom`, `Lwd`, `Cartograph`) и
переводится в значение базы (`Автономный`, `LWD`, `Картограф`). Справочник
namеренно живёт на сервере: две копии соответствия неизбежно разошлись бы.

### Коды ответов

| Код | Смысл |
| --- | --- |
| `unauthorized` (401) | токен не передан, недействителен или отозван |
| `device_not_found` (404) | прибора с таким серийным номером нет в базе |
| `device_ambiguous` (409) | в базе несколько приборов с одним серийным номером |
| `duplicate` (409) | файл с таким содержимым уже загружен в этот раздел |
| `file_too_large` (413) | файл больше 20 МБ |
| `rate_limited` (429) | исчерпан часовой лимит загрузок |
| `schema_not_ready` (500) | не выполнен скрипт `sql/2026-08-15-device-registry-api.sql` |
| `server_error` (500) | внутренняя ошибка; подробности — в `logs/security.log` |

Ответ всегда JSON: контроллер перехватывает необработанные исключения и фатальные
ошибки, а вывод текста ошибок в тело ответа отключён. Иначе исключение mysqli
уходило бы клиенту HTML-фаталом с кодом 200 и путями на сервере.

При `duplicate` в ответе приходит `existing` с именем и датой уже загруженного
файла. Повторная отправка с `force=1` создаёт вторую копию — это делается только
после явного подтверждения пользователем.

## Ограничение на типы файлов

Через API принимаются только файлы данных прибора: `.bin`, `.biv`, `.DEV`.
Отчёты, документы и архивы загружаются через сайт, где действует прежний широкий
список расширений.

## Создание токена пользователем

1. Войти на сайт под своей учётной записью.
2. Открыть «Профиль» → карточка «Доступ для приложения «Визуализация данных»».
3. Нажать «Создать токен» и указать название (например, «Ноутбук в лаборатории»).
4. Скопировать показанный токен — второй раз он не показывается.
5. В приложении: верхнее меню → «Связь с БД» → вставить токен → «Сохранить».

Токены перечислены в той же карточке с датой создания и датой последнего
использования; кнопка «Отозвать» немедленно прекращает доступ.

## Что нужно сделать для запуска

1. Выложить на сервер новые и изменённые файлы (список выше).
2. Один раз выполнить `sql/2026-08-15-device-registry-api.sql` в phpMyAdmin —
   он добавляет колонку `uploaded_files.sha256`.
3. Открыть «Профиль» и создать токен — таблица `api_tokens` создастся сама.
4. Проверить связь из приложения кнопкой «Проверить соединение».

Проверка вручную, без приложения:

```bash
curl -X POST "https://amk-horizon.ru/front.php?c=Api&a=whoami" -H "Authorization: Bearer <токен>"
```
