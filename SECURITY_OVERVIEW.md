# Обзор безопасности

Документ описывает текущую модель безопасности приложения учёта приборов АМК «Горизонт».

Актуальность: 2026-05-09.

## 1. Основные компоненты

| Компонент | Файл | Назначение |
| --- | --- | --- |
| `BaseController` | `src/Controller/BaseController.php` | Общие методы защиты для контроллеров. |
| `SecurityService` | `src/Service/SecurityService.php` | CSRF, rate limiting, sanitization, SQL whitelist, security headers, логи. |
| `PageSecurityHelper` | `src/Security/PageSecurityHelper.php` | Защита standalone-страниц. |
| `security_init.php` | `security_init.php` | Инициализация защиты страниц верхнего уровня. |
| `AuthController` | `src/Controller/AuthController.php` | Вход, выход и проверка сессии. |

## 2. Модель доступа

Приложение использует сессионную аутентификацию. Закрытые операции должны вызывать `requireAuth()`. Административные операции должны дополнительно вызывать `requireAdmin()`.

Роли:

- обычный пользователь - работа с приборами, файлами, сообщениями и AI-агентом;
- администратор - расширенные операции, административная панель, SQL-инструменты и управление пользователями.

## 3. Защита запросов

Используемые механизмы:

- проверка авторизации на сервере;
- CSRF-токены для изменяющих операций;
- rate limiting на чувствительных endpoint-ах;
- очистка строк через `sanitizeString()`;
- проверка числовых параметров через `validateInt()`;
- подготовленные выражения mysqli;
- централизованный JSON-ответ через `jsonResponse()`.

Для новых endpoint-ов не следует полагаться только на клиентскую валидацию.

## 4. HTTP-заголовки

`SecurityService::setSecurityHeaders()` устанавливает:

- `X-Content-Type-Options: nosniff`;
- `X-Frame-Options: DENY`;
- `X-XSS-Protection: 1; mode=block`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- `Content-Security-Policy`.

CSP допускает локальные ресурсы, Font Awesome/CDNJS, Google Fonts, изображения `self`, `data:` и `https:`.

## 5. SQL-безопасность

Правила:

- пользовательский ввод не конкатенируется в SQL;
- все CRUD-операции используют prepared statements;
- SQL от AI-агента допускается только для чтения;
- запреты AI-агента: `users.password`, `uploaded_files.file_data`, DML/DDL, множественные запросы;
- динамические имена таблиц проверяются через whitelist.

`SecurityService::validateSQLQuery()` разрешает только команды `SELECT`, `SHOW`, `DESCRIBE`, `EXPLAIN` и блокирует опасные конструкции.

## 6. AI-агент

AI-агент имеет отдельные ограничения безопасности:

- локальные intent-ы выполняются через предопределённый SQL;
- LLM-fallback выполняет только read-only SQL;
- схема БД для LLM формируется контролируемо через `DatabaseSchemaService`;
- контекст диалога хранится в сессии пользователя;
- при отсутствии контекста для фраз «этот прибор» агент просит уточнение, а не передаёт запрос модели для угадывания.

Логи AI-агента находятся в `logs/ai`.

## 7. Файлы

Файловые операции выполняются через `FileController`:

- загрузка с проверкой размера и метаданных;
- получение списка файлов по прибору;
- скачивание через серверный endpoint;
- удаление и переименование с проверкой прав.

При работе с AI-агентом содержимое `uploaded_files.file_data` не должно попадать в SQL-ответы без явного служебного сценария.

## 8. Логирование

Security-события пишутся в `logs/security.log` в JSON Lines формате.

Типовые события:

- неуспешные попытки авторизации;
- превышение rate limit;
- отказ в административном доступе;
- ошибки валидации;
- действия с файлами и сообщениями;
- запросы к AI-агенту.

## 9. Практические требования

Для любого нового контроллера:

1. Наследовать `BaseController`.
2. В начале закрытого метода вызвать `requireAuth()`.
3. Для административного метода вызвать `requireAdmin()`.
4. Для POST/PUT/DELETE проверить CSRF, если метод вызывается из формы или UI.
5. Валидировать все входные параметры.
6. Использовать prepared statements.
7. Логировать значимые события безопасности.
8. Возвращать единый JSON-ответ.

## 10. Ограничения и зона внимания

- В `config.php` присутствуют чувствительные параметры; при production-сопровождении их следует вынести в защищённое окружение.
- Логи не должны содержать пароли, API-ключи и содержимое бинарных файлов.
- CSP содержит `unsafe-inline`; при дальнейшем развитии frontend желательно перейти на nonce/hash-подход.
- При добавлении новых таблиц нужно обновлять whitelist и инструкции AI-агента.
