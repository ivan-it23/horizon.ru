# Модульная архитектура AI-агента

## Обзор

Система AI-агента была рефакторена из монолитного файла `database_query_handler_improved.php` в модульную архитектуру для улучшения масштабируемости, читаемости и поддерживаемости кода.

## Структура модулей

### 1. QueryAnalyzer (`src/Service/QueryAnalyzer.php`)
**Назначение**: Анализ естественно-языковых запросов пользователя

**Основные методы**:
- `analyzeQuery($userQuery)` - анализ запроса и определение типа
- `setLastDevice($serialNumber, $caseNumber)` - установка контекста последнего прибора
- `getLastDeviceSerialNumber()` - получение серийного номера
- `getLastDeviceCaseNumber()` - получение номера корпуса

**Обрабатываемые типы запросов**:
- `count_devices_by_type` - подсчёт приборов по типу
- `count_all_devices` - общий подсчёт приборов
- `count_repairs` - подсчёт ремонтов
- `device_info_by_serial/case` - краткая информация о приборе
- `full_device_info_by_serial/case` - полная информация о приборе
- `list_devices_by_type` - список приборов по типу
- `recent_repairs` - последние ремонты
- `device_statistics` - статистика приборов

### 2. QueryExecutor (`src/Service/QueryExecutor.php`)
**Назначение**: Выполнение статистических запросов к базе данных

**Основные методы**:
- `executeQuery($queryAnalysis)` - диспетчер запросов
- `countDevicesByType($deviceType)` - подсчёт по типу
- `countAllDevices()` - общий подсчёт
- `countRepairs()` - подсчёт ремонтов
- `listDevicesByType($deviceType)` - список приборов
- `getRecentRepairs($limit)` - последние ремонты
- `getDeviceStatistics()` - статистика

### 3. DeviceInfoManager (`src/Service/DeviceInfoManager.php`)
**Назначение**: Работа с информацией о приборах и их составе

**Основные методы**:
- `getDeviceInfoBySerial($serialNumber)` - информация по серийному номеру
- `getDeviceInfoByCase($caseNumber)` - информация по номеру корпуса
- `getFullDeviceInfo($serialNumber, $caseNumber)` - полная информация
- `fetchRelatedData()` - получение связанных данных

**Получаемые данные**:
- Основные параметры прибора
- Состав прибора (платы, компоненты)
- История ремонтов
- Данные о производстве, испытаниях, контроле
- Информация о прекращении эксплуатации
- Дополнительные сведения

### 4. ResponseFormatter (`src/Service/ResponseFormatter.php`)
**Назначение**: Форматирование ответов в читаемый Markdown-формат

**Основные методы**:
- `formatDeviceInfo($device, $composition, $repairs)` - краткая информация
- `formatFullDeviceInfo($data)` - полная информация
- `formatResultsAsMarkdownTable($data)` - таблицы Markdown

**Форматирование включает**:
- Структурированные заголовки
- Эмодзи для визуального разделения
- Иерархические списки
- Таблицы данных
- Условное отображение полей

### 5. ContextManager (`src/Service/ContextManager.php`)
**Назначение**: Управление контекстом диалога

**Основные методы**:
- `extractAndSaveContext($responseText)` - извлечение контекста из ответа
- `getCurrentContext()` - получение текущего контекста
- `setContext($serialNumber, $caseNumber)` - установка контекста
- `clearContext()` - очистка контекста
- `hasContext()` - проверка наличия контекста

**Особенности**:
- Автоматическое устаревание контекста (30 минут)
- Сохранение в сессии пользователя
- Извлечение данных из текста ответа

### 6. DatabaseQueryHandler (`src/Service/DatabaseQueryHandler.php`)
**Назначение**: Главный координатор всех модулей

**Основные методы**:
- `analyzeQuery($userQuery)` - анализ запроса
- `executeQuery($queryAnalysis)` - выполнение запроса
- `executeNaturalLanguageQuery($sql)` - выполнение SQL-запросов
- `extractAndSaveContext($responseText)` - управление контекстом

**Координация**:
- Создание и управление экземплярами всех модулей
- Маршрутизация запросов к соответствующим модулям
- Синхронизация контекста между модулями

## Преимущества модульной архитектуры

### 1. Разделение ответственности
- Каждый модуль отвечает за свою область
- Четкие границы между функциональностью
- Легче тестировать отдельные компоненты

### 2. Масштабируемость
- Легко добавлять новые типы запросов
- Простое расширение функциональности
- Возможность замены отдельных модулей

### 3. Читаемость кода
- Логическая группировка методов
- Понятная структура файлов
- Улучшенная документация

### 4. Поддерживаемость
- Изолированные изменения
- Меньше конфликтов при разработке
- Проще отладка

### 5. Переиспользование
- Модули можно использовать независимо
- Возможность создания новых сервисов
- Гибкая архитектура

## Миграция

### Изменения в контроллере
```php
// Старый код
require_once __DIR__ . '/../../database_query_handler_improved.php';
$dbHandler = new \DatabaseQueryHandler($conn);

// Новый код
$dbHandler = new \App\Service\DatabaseQueryHandler($conn);
```

### Совместимость
- Все публичные методы сохранены
- Обратная совместимость с существующим кодом
- Плавная миграция без нарушений
