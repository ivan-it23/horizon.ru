# Состояние рефакторинга AI-агента

Документ фиксирует текущее состояние рефакторинга AI-агента и его сервисного слоя.

Актуальность: 2026-05-09.

## 1. Цель рефакторинга

Первоначальная логика AI-агента была вынесена из монолитного обработчика в набор специализированных сервисов. Цель - сделать маршрутизацию запросов, выполнение SQL, форматирование и управление контекстом сопровождаемыми отдельно.

## 2. Текущая структура

| Модуль | Файл | Ответственность |
| --- | --- | --- |
| Контроллер AI | `src/Controller/AiAgentController.php` | HTTP/SSE, LLM-вызовы, логирование. |
| Координатор | `src/Service/DatabaseQueryHandler.php` | Связь анализатора, исполнителя, контекста и форматирования. |
| Анализатор | `src/Service/QueryAnalyzer.php` | Intent-ы и ссылки на контекст. |
| Исполнитель | `src/Service/QueryExecutor.php` | Предопределённые SQL-запросы. |
| Карточка прибора | `src/Service/DeviceInfoManager.php` | Сбор полной информации о приборе. |
| Форматирование | `src/Service/ResponseFormatter.php` | Markdown-ответы. |
| Шаблоны | `src/Service/ResponseTemplateManager.php` | Типовые ответы. |
| Контекст | `src/Service/ContextManager.php` | Стек фреймов диалога. |
| Схема БД | `src/Service/DatabaseSchemaService.php` | Prompt-контекст БД и read-only SQL. |

## 3. Выполненные изменения

- AI-агент подключён через `AiAgentController`.
- Типовые запросы обрабатываются локально без LLM.
- Нестандартные запросы проходят через LLM-fallback с read-only SQL.
- Ответы форматируются в Markdown.
- Добавлен streaming-режим через SSE.
- Добавлен стек контекстных фреймов диалога.
- Добавлена защита от LLM-угадывания при отсутствующем контексте.
- Логи AI-запросов сохраняются в `logs/ai`.

## 4. Контекстные фреймы

Текущий `ContextManager` хранит не только последний прибор, но и стек структурированных результатов:

- найденные приборы;
- типы приборов;
- строки SQL-результата;
- topic результата;
- summary ответа;
- SQL-запросы LLM, если они были.

Это позволяет корректно обрабатывать:

- «этот прибор»;
- «этим прибором»;
- «первый из списка»;
- «эти приборы»;
- «по нему»;
- «по этому типу».

## 5. Intent-ы локальной обработки

Поддерживаются:

- подсчёт приборов;
- подсчёт ремонтов;
- списки по типу прибора;
- последние ремонты;
- последний ремонт;
- приборы в ремонте;
- приборы на испытаниях;
- статистика приборов;
- прибор с максимальным числом ремонтов;
- причины ремонтов по прибору;
- карточка прибора по серийному номеру или корпусу;
- полная карточка прибора;
- приветствие, справка и прощание.

## 6. Что важно учитывать дальше

- Новые часто используемые вопросы лучше добавлять как локальные intent-ы.
- Любой новый intent должен возвращать структурированные данные для контекста, если результат может стать объектом следующего вопроса.
- Streaming-режим не должен закрывать сессию до сохранения контекстных фреймов.
- При изменении БД нужно синхронно обновлять `DatabaseSchemaService` и `ai_agent/ai_agent_instructions.md`.

## 7. Риски

- Regex-анализатор требует регулярного пополнения формулировок.
- LLM-fallback зависит от полноты схемы БД в prompt.
- Контекст хранится в PHP-сессии, поэтому сброс сессии или очистка истории удаляют фреймы.
- В проекте пока нет автоматических тестов для intent-ов и prompt-регрессий.

## 8. Рекомендации

- Добавить unit-тесты для `QueryAnalyzer`.
- Добавить регрессионные сценарии для контекстных запросов.
- Вынести SQL-шаблоны типовых запросов в отдельный слой, если число intent-ов существенно вырастет.
- Добавить диагностический endpoint для просмотра текущего стека контекста в режиме разработки.
