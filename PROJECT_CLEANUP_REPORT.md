# Состояние структуры проекта и документации

Документ описывает текущую структуру документации и правила её сопровождения.

Актуальность: 2026-05-09.

## 1. Назначение

Проект содержит несколько типов документации:

- вводная документация для быстрого понимания проекта;
- техническая документация по архитектуре;
- документация по безопасности;
- документация по AI-агенту;
- отчёты о состоянии рефакторинга и структуры.

Документы приведены к корпоративному стилю: без эмодзи, без рекламных формулировок, с ориентацией на разработчиков.

## 3. Правила документации

- Документация пишется для разработчиков и сопровождающих инженеров.
- Формулировки должны быть точными и проверяемыми по коду.
- Не использовать эмодзи, рекламные лозунги и утверждения без технического смысла.
- Не указывать реальные пароли, API-ключи и приватные параметры.
- Если меняется публичный endpoint, сервис, таблица БД или поведение AI-агента, документация обновляется в том же изменении.
- Исторические отчёты должны отражать текущее состояние, а не старые обещания.

## 4. Структура проекта

```text
src/Controller/      контроллеры
src/Service/         сервисный слой
src/Security/        security-помощники
assests/js/          frontend-логика
assests/css/         дизайн-система и стили страниц
ai_agent/            UI, JS, CSS и инструкции AI-агента
logs/                журналы
icons/, images/      статические ресурсы
```

## 5. Что считать устаревшей документацией

Документ требует обновления, если в нём:

- указан несуществующий файл;
- описан удалённый controller/action;
- приведён старый список таблиц;
- есть устаревшие размеры классов или строки кода;
- описано поведение AI-агента без контекстных фреймов;
- есть эмодзи или декоративные блоки, неуместные для корпоративной документации;
- указана дата, не соответствующая фактическому состоянию.

## 6. Рекомендуемый порядок обновления

1. Проверить `rg --files -g "*.md"`.
2. Сверить controller/action через `rg -n "class |public function" src`.
3. Сверить сервисы через `rg -n "class " src/Service`.
4. Сверить frontend-модули в `assests/js` и `assests/css`.
5. Обновить `DatabaseSchemaService` и `ai_agent/ai_agent_instructions.md`, если менялась БД.
6. Запустить `git diff --check`.
